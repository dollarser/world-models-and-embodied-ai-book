# 许可、数据与密钥政策

## 1. 仓库许可证

本仓库中的原创正文、原创图表、教学材料和自有代码统一采用 MIT License，完整文本见仓库根目录 `LICENSE`。MIT 允许商业使用、复制、修改、合并、发布、分发、再许可和销售，但再分发时必须保留版权声明与许可声明，且内容按“原样”提供、不附带担保。

MIT 只覆盖本项目有权授权的原创内容，不改变第三方代码、数据、模型权重、论文、图片、字体和其他资产的许可证或使用条款。贡献内容在合入前必须确认贡献者有权按仓库许可证提供；如需引入不能按 MIT 再分发的材料，应只保存引用或获取说明，不直接纳入仓库。

## 2. 第三方资产台账

每项第三方资产至少记录：

```text
名称 | 类型 | 来源 URL | 版本/commit | 许可证
允许用途 | 是否可再分发 | 获取日期 | 校验和 | 使用章节
```

代码许可证、模型权重许可、训练数据许可和评测数据许可必须分别核验，不能因同一项目的代码开源而推断其他资产也可再分发。

## 3. 数据分级

- `fixture`：体积小、许可明确、可随书再分发；核心 smoke 只依赖此级别；
- `downloadable`：可按脚本获取，但不得提交原始数据；
- `application_required`：需要申请、签署条款或凭证；不得作为必做入口；
- `restricted`：仅允许在特定机构、地域或用途下使用；只做案例说明；
- `private`：包含个人、车辆、位置或其他敏感信息；未经单独批准不得进入仓库。

所有数据准备脚本必须支持 dry-run，并在下载前显示预计下载量、磁盘占用、许可链接和校验方式。大型下载与付费访问必须由用户显式确认。

## 4. 仓库内容边界

默认不提交：

- 完整数据集、视频和大型仿真资产；
- 模型权重、checkpoint 和派生特征；
- 未脱敏的日志、真实轨迹和传感器记录；
- 访问令牌、API key、cookie、签名 URL 和云凭证；
- 许可证不允许再分发的论文图片和表格。

仓库只保存必要的元数据、下载脚本、校验和、微型 fixture、结构化结果和来源说明。

## 5. API 与隐私

- 密钥只通过运行时 secret 或环境注入，不写入命令示例、日志或实验卡；
- 闭源 API 实验记录模型快照、日期、参数、费用和响应摘要，但先移除密钥与个人数据；
- 未经许可，不向第三方 API 上传真实机器人、驾驶或用户数据；
- 归档响应前核验供应商条款是否允许保存和再分发；
- API 基线必须提供无需凭证的归档响应或本地替代路径。

## 6. 发布门禁

以下任一情况阻止发布：

- 根目录 `LICENSE` 缺失，或发布说明错误描述仓库许可范围；
- 必做 fixture 许可不清楚；
- 图表来源或再分发权缺失；
- 实验卡仍包含 `license pending` 却标为 `reproducible`；
- 仓库或生成站点包含密钥、个人数据或受限资产。
