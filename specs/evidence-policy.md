# 证据与声明规范

## 1. 二维标注

来源成熟度：

- `P`：同行评审论文；
- `A`：预印本或完整研究报告；
- `O`：官方代码、模型卡、数据卡或基准文档；
- `V`：公司博客、产品页、演示或发布会；
- `T`：第三方分析、新闻或社区整理。

可复现状态：

- `R0`：只有声明或演示；
- `R1`：公开部分资产；对闭源接口，只表示在锁定模型快照和协议下归档了可审计行为，不表示内部权重、训练过程或未来服务行为可复现；
- `R2`：官方命令在声明环境中可运行；
- `R3`：存在独立复现或跨团队验证；
- `R4`：本书在锁定环境下复现了指定主张并公开日志。

来源与复现状态必须分开记录。论文发表不自动意味着 `R3`，仓库存在也不自动意味着 `R2`。

`P` 只在出版社、会议/期刊页面或论文一手元数据明确显示已接收/发表场次时使用。只有 arXiv 提交、arXiv DOI、作者项目页或“已投稿”不能证明同行评审；场次尚未确认时保守标为 `A`，后续再升级而不是预先升级。

## 2. 声明分类

正文关键声明使用稳定 ID，例如 `CLAIM-06-04`，并标明它属于：

- `fact`：一手来源直接支持的事实、本书明确约定的定义，或当前仓库可直接核对的合同；转述论文数字时，事实对象是“该论文报告了什么”，不是“该结论已由本书复现”；
- `result`：本书已执行实验直接得到的结果；必须由同章实验卡的 `claim_ids` 反向绑定，正文必须同时写清 fixture、范围与不能外推之处；
- `inference`：由多个证据推导的解释；
- `recommendation`：作者基于目标读者和资源给出的选择；
- `unverified`：尚待目标环境验证的主张。

声明定义采用唯一的机器可读形式：

```text
`CLAIM-NN-MM`（fact|result|inference|recommendation|unverified）：声明正文
```

圆括号内只能写一个规范类型。`[P/A/O/V/T,R0–R4]`、`EXP-*`、`BENCH-*`、限定语和“按本书定义”等信息放在相邻正文或表格字段中，不得塞入类型字段。每个 ID 只能定义一次，章节号必须与所在章节一致；正文定义集与 `book-manifest.json` 登记集必须双向相等。

类型不是“可信度等级”。`recommendation` 可以理由充分但仍是作者取舍，`fact` 也可能只由快速变化的官方页面支持。来源成熟度、可复现状态、声明类型三者必须分别记录。

所有 `fact` 还必须在 `specs/fact-evidence.json` 登记证据基类、来源成熟度、核查日期适用的证据锚点和支持边界。登记范围与正文 `fact` 集合双向相等：本书定义或当前仓库合同可以使用本地锚点；论文、官方资产和供应商声明必须使用外部锚点。供应商声明只能登记为 `vendor_statement` / `V`，不能因进入登记表而升级为独立验证。

所有 `inference` 必须在 `specs/inference-evidence.json` 明确登记至少两个前提、证据锚点、一个会削弱结论的反例/反证条件，以及适用范围。登记集与正文 `inference` 集合双向相等。推断不能只复述作者偏好；若没有可审查的前提或反证条件，应改为 `recommendation`。

## 3. 最小记录

```text
声明 ID | 声明 | 类型 | 来源 | 核查日期 | 任务/基线
资产状态 | 实验 ID | 复现状态 | 限制 | 负责人
```

## 4. 使用外部结果

- 性能数字回到原论文表格或官方结果文件；
- 供应商博客只能证明供应商做出了该声明；
- README 的资源或速度数字不得改写成本书实测；
- 综述用于发现材料和校验分类，关键结论回到一手来源；
- 快速变化的模型版本与排行榜进入案例卡，不进入稳定公式和章节结构。

## 5. 本书实验结果

只有满足以下条件才能写为“本书复现”：

1. 实验卡完整；
2. 代码与第三方依赖提交已锁定；
3. 数据版本、许可与校验和可追溯；
4. 训练和评测日志存在；
5. 指标由报告脚本生成；
6. 目标资源档位经过实测。

当前无 GPU 阶段的 CPU smoke 只能证明接口和数据流可运行，不能证明 24GB GPU 训练成本、收敛、样本效率或实时性能。

在 `smoke` 阶段可以使用 `result` 记录确定性 fixture 的实际输出，但必须写成“该固定反例验证了某个接口/算术/失败机制”，不得改写成模型效果、真实故障率、总体规律或目标硬件性能。若正文只有计划、预期或待跑数字，类型必须是 `unverified`，不能预占 `result`。

每条 `result` 的机器定义句必须直接包含“不证明、不外推、只适用于、不是”等边界语义，不能只把限制埋在章节末尾。实验卡绑定保证结果来自哪里，定义句边界说明它不能被解释成什么；两者缺一不可。
