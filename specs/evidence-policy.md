# 证据与声明规范

## 1. 二维标注

来源成熟度：

- `P`：同行评审论文；
- `A`：预印本或完整研究报告；
- `O`：官方代码、模型卡、数据卡或基准文档；
- `V`：公司博客、产品页、演示或发布会；
- `T`：第三方分析、新闻或社区整理。

可复现状态：

- `R0`：只有声明或演示；
- `R1`：公开部分资产；对闭源接口，只表示在锁定模型快照和协议下归档了可审计行为，不表示内部权重、训练过程或未来服务行为可复现；
- `R2`：官方命令在声明环境中可运行；
- `R3`：存在独立复现或跨团队验证；
- `R4`：本书在锁定环境下复现了指定主张并公开日志。

来源与复现状态必须分开记录。论文发表不自动意味着 `R3`，仓库存在也不自动意味着 `R2`。

## 2. 声明分类

正文关键声明使用稳定 ID，例如 `CLAIM-06-04`，并标明它属于：

- `fact`：来源直接支持的事实；
- `result`：本书实验直接得到的结果；
- `inference`：由多个证据推导的解释；
- `recommendation`：作者基于目标读者和资源给出的选择；
- `unverified`：尚待目标环境验证的主张。

## 3. 最小记录

```text
声明 ID | 声明 | 类型 | 来源 | 核查日期 | 任务/基线
资产状态 | 实验 ID | 复现状态 | 限制 | 负责人
```

## 4. 使用外部结果

- 性能数字回到原论文表格或官方结果文件；
- 供应商博客只能证明供应商做出了该声明；
- README 的资源或速度数字不得改写成本书实测；
- 综述用于发现材料和校验分类，关键结论回到一手来源；
- 快速变化的模型版本与排行榜进入案例卡，不进入稳定公式和章节结构。

## 5. 本书实验结果

只有满足以下条件才能写为“本书复现”：

1. 实验卡完整；
2. 代码与第三方依赖提交已锁定；
3. 数据版本、许可与校验和可追溯；
4. 训练和评测日志存在；
5. 指标由报告脚本生成；
6. 目标资源档位经过实测。

当前无 GPU 阶段的 CPU smoke 只能证明接口和数据流可运行，不能证明 24GB GPU 训练成本、收敛、样本效率或实时性能。
