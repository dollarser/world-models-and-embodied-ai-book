# 全书术语与符号基线

> 状态：v1 草案。正文首次使用术语时可补充直觉解释，但不得改变此处的基本边界。

## 核心术语

| 术语 | 本书工作定义 | 不应混同 |
| --- | --- | --- |
| 环境 | 接收动作并产生后续状态与观测的系统 | 仅指仿真器 |
| 状态 | 足以描述任务相关环境条件的变量 | 原始像素 |
| 信念状态 | 在部分可观测条件下对潜在状态的内部估计 | 单帧视觉特征 |
| 观测 | 传感器在某时刻提供的数据 | 完整真实状态 |
| 动作 | 智能体施加到环境或下层控制器的决策量 | 语言解释或规划文本 |
| 策略 | 从观测、状态或信念映射到动作分布的规则 | 世界模型 |
| 世界模型 | 对任务相关状态及其随动作演化规律的可学习表示 | 任意视频生成器 |
| 转移模型 | 预测状态在动作条件下如何变化的模型 | 无动作条件的编码器 |
| 奖励 | 对单步结果或转移偏好的标量反馈 | 成功率、价值函数 |
| 价值 | 给定状态或动作后未来累计回报的估计 | 即时奖励 |
| rollout | 从初始条件开始连续推进环境或模型得到的轨迹 | 单次前向 |
| imagined rollout | 在学习到的世界模型内部生成的轨迹 | 真实环境轨迹 |
| 开环评测 | 不让模型输出持续影响后续输入的评测 | 离线一定等于开环 |
| 闭环评测 | 动作影响环境，后续观测再反馈给策略的评测 | 单步动作准确率 |
| 模型利用 | 策略主动利用世界模型误差获得虚假高回报 | 一般过拟合 |
| 仿真器 | 通过显式规则、数值方法或学习模型推进环境的系统 | 世界模型的同义词 |
| VLA | 将视觉、语言和机器人状态映射为动作的策略架构族 | 自动具有世界模型 |
| occupancy | 对空间位置被占用概率或状态的表示 | 仅指 3D 重建 |
| affordance | 环境或对象对特定动作所提供的可能性 | 物体类别 |
| 三态 occupancy | 将空间证据区分为 `free`、`occupied` 与 `unknown` | 把未检测或视野外默认当作 free |
| 语义 occupancy | 在空间占用之上附加类别、实例或属性的表示 | 只有对象检测框或类别列表 |
| occupancy flow | 对未来占用及其运动方向/速度的时序表示 | 单帧静态 occupancy |
| BEV | 将空间投影或聚合到鸟瞰平面的表示 | 自动保留完整高度、遮挡与三维碰撞 |
| Sim2Real | 从仿真训练/验证迁移到真实系统的过程 | 仿真分数直接代表实机分数 |
| 坐标系 / frame | 规定原点、轴向、手系与单位的参考框架 | 仅有相同 shape 的数组 |
| 位姿 | 一个刚体相对指定 frame 的位置与朝向 | 只有位置坐标 |
| 正运动学 | 从本体配置计算末端或刚体位姿 | 环境动力学或策略 rollout |
| 逆运动学 | 从目标位姿求满足约束的本体配置 | 保证无碰撞或动力学可执行 |
| JEPA | 从上下文预测目标区域表示的联合嵌入预测架构族 | 任意无解码器的视觉编码器 |
| probe | 在固定或受限表征上训练的诊断读出器 | 证明策略会使用该信息或闭环有效 |
| renderer | 从给定状态、场景或描述生成传感器外观的组件 | 自动包含状态转移与交互规则 |
| learned simulator | 根据动作推进学习状态并产生后续观测的模型 | 只生成一段无反馈视频的模型 |
| counterfactual | 固定历史与其余条件、只改变干预变量所得的替代未来 | 任意随机生成的另一段视频 |
| aleatoric 不确定性 | 在给定完整任务条件下仍存在的结果随机性或多模态性 | 模型因数据不足而不知道 |
| epistemic 不确定性 | 由数据覆盖、参数或模型知识不足引起、原则上可随证据增加而降低的不确定性 | 单个模型多采样得到的多样性 |
| Diffusion Policy | 在观测条件下通过动作去噪过程采样动作或动作块的策略族 | 任意含噪训练或图像扩散模型 |
| Flow Matching | 通过回归条件向量场连接 base 与目标分布的生成建模方法 | 自动等于一步采样或 rectified flow |
| prediction horizon | 策略一次预测的未来动作长度 | 实际盲执行的动作步数 |
| execution horizon | 一个预测块中实际执行后再重规划的步数 | prediction horizon 或控制频率 |
| action token | 将连续/离散动作或动作序列编码成离散词元后的表示 | 自然语言词元或已解码控制量 |
| action grounding | 将语义/模型输出映射为指定本体可执行动作的过程 | 文本看起来合理或字段可解析 |
| action schema | 规定动作字段、顺序、frame、单位、频率、horizon、范围和版本的合同 | 只有 tensor shape |
| embodiment | 传感器、机构、动作空间与控制接口共同定义的本体配置 | 仅机器人型号名称 |
| canonical action | 为跨数据/本体对齐定义的版本化中间动作语义 | 自动能由每个本体直接执行的万能动作 |
| data mixture | 带来源与采样权重的多数据集训练分布 | 简单拼接文件或按帧等权 |
| 正迁移 / 负迁移 | 加入来源数据后目标协议指标相对目标单独训练提高/降低 | schema 错配或只看混合总体分数 |

## 统一符号

| 符号 | 含义 |
| --- | --- |
| `e_t` | 时刻 `t` 的真实环境状态；通常不可完全观测 |
| `o_t` | 时刻 `t` 的观测 |
| `a_t` | 时刻 `t` 执行的动作 |
| `z_t` | 模型内部的潜在状态或信念状态 |
| `h_t` | 确定性循环状态 |
| `s_t` | 随机潜变量；在 RSSM 章节与 `h_t` 配对使用 |
| `r_t` | 与时刻 `t` 转移相关的奖励 |
| `\gamma` | 折扣因子 |
| `\pi` | 策略 |
| `p_\theta` | 参数为 `\theta` 的生成或动力学模型 |
| `q_\phi` | 参数为 `\phi` 的近似后验或编码模型 |

## 写作规则

- “状态”必须说明是真实状态、观测状态还是模型潜在状态；
- 几何量必须说明 frame、单位、时间戳和变换方向；
- “动作”必须说明动作类型、frame、单位、控制频率、持续时间与下层安全约束；
- “probe”必须说明表征层、token/池化、head 容量、切分、负对照与训练范围；
- “动作条件”必须说明动作是否真实可执行、如何对齐、模型是否通过同状态干预测试；
- “occupancy”必须说明 frame、范围、分辨率、时间、free/occupied/unknown 规则和动态更新；
- “affordance”必须说明本体、动作族、约束、预测时刻和可执行性验证；
- “生成式动作”必须说明条件、动作表示、prediction/execution horizon、采样器、调用数、随机种子与安全筛选；
- “VLA”必须说明视觉/语言/状态输入、动作头、action schema、grounding、本体、执行频率和闭环评测；
- “跨本体迁移”必须说明 canonical schema、adapter、mixture 权重、目标单独训练基线与逐本体迁移矩阵；
- “实时”必须同时给出硬件、batch、输入尺寸和延迟统计方式；
- “复现”必须对应 `R0–R4` 的具体状态；
- “开源”必须区分代码、权重、训练数据、评测数据和许可；
- “提升”必须说明相对基线、指标、统计区间和实验 ID。
