# 《世界模型与具身智能：从表征、预测到行动》书籍设计方案 v0.6

> 面向计算机视觉算法工程师的开源教材与可复现实验书。
>
> 研究基线核查日期：2026-08-31（v0.5 完成一轮针对 2026 年新论文、新基准与开源教学项目的复核；v0.6 进一步校准资源档位、数据可用性、仿真边界和基线对照）。稳定知识写入正文，快速变化的模型版本与产业信息进入在线案例卡和更新台账。

## 0. 本版结论

本方案不再把“经典论文 + 当季热门模型”直接排成目录，而采用一条稳定的教学主线：

> **观测如何成为状态，状态如何支持预测，预测如何支持决策，决策如何在真实闭环中被验证。**

全书调整为 **7 部分、22 章、2 条贯穿实验线、1 条自动驾驶案例线、1 个综合项目**。主干覆盖世界模型、机器人策略、VLA 与真实系统闭环。3D 视觉按零基础设计；自动驾驶贯穿正文多个核心章节；人形机器人和快速变化的产业版本作为横向案例，不与基础概念争夺章节。

### v0.4 → v0.5 的关键变化（研究复核结论）

结论先行：v0.4 的教学骨架（闭环主线、四轴判断、来源成熟度×可复现状态、资源档位）经得住 2025–2026 这一波新论文和新产品的检验——没有任何一个新工作要求推翻主干，只需要把它们放进已有的位置。这本身印证了“正文讲架构模式、版本进案例卡”的设计是对的。具体调整：

| 复核发现 | v0.5 决策 |
| --- | --- |
| DreamerV3 已于 2025 年在 *Nature* 正式发表；其继任者 Dreamer 4（Hafner 等，2025-09）用 shortcut forcing + 因果 tokenizer 实现单 GPU 实时交互推理，且已有社区 PyTorch 实现 | 第6/8章以 mini-RSSM、Dreamer-lite 和 DreamerV3 debug 配置承担稳定主实验；Dreamer 4 作为进阶案例。实时推理不等于完整训练可在 24GB 单卡完成，社区实现必须经过固定提交与资源审计后才能进入必做实验 |

### v0.5 → v0.6 的关键变化（算力适配与基线补充）

本版对自动驾驶仿真、机器人仿真加速、闭源多模态基线和视频数据锚点进行了二次核验。保留 CARLA、MuJoCo、LIBERO 主线，同时补充更省资源的默认入口和更严格的使用边界：

| 审查建议 | 核实结论 | v0.6 决策 |
| --- | --- | --- |
| 用 MetaDrive 替代 CARLA 作为 S/M 档自动驾驶闭环默认环境 | MetaDrive 轻量、可 CPU 运行并支持点云/RGB/BEV 等观测；官方给出的“最高上千 FPS”是特定配置上限，不是通用性能承诺。ScenarioNet 可接入真实驾驶日志，但源数据许可与下载条件必须单独核验 | 第3.5节和第13章“已锁定决策”把 MetaDrive 的内置程序化场景列为 S/M 档默认闭环入口；CARLA、录制数据和受许可约束的真实日志用于更高视觉真实性的扩展 |
| 引入 MuJoCo MJX 支持更大吞吐的后训练 | MJX 是 MuJoCo 官方硬件加速接口，包含 JAX 与 Warp 实现；它继承 MuJoCo 的模型体系，但在功能覆盖、碰撞、求解器、自动微分和数值行为上并非与 C MuJoCo 完全等价 | 第3.5节和第19章把 MJX 列为 M/L1 档可选加速项；切换前必须通过功能兼容检查和跨后端 rollout 对照 |
| 增设版本锁定的商用 VLM API 零样本/少样本控制基线 | 该基线不占本地显存，但会引入费用、延迟、限流、网络、数据治理和供应商版本漂移，不能只按 S/M/L 显存档位衡量 | 第15章和第20章将其作为可选闭源提示基线，默认 `[V,R0]`；只有锁定模型快照并保存请求、响应、参数、日期和费用的具体实验才可升级为 `[V,R1]` |
| 引入 Ego4D、EPIC-KITCHENS、OpenDV 等视频数据 | 这些数据的许可、获取方式、动作标签和磁盘成本不同。Ego4D 需要申请访问；OpenDV 主要提供驾驶视频及语言标注，不能默认视为控制动作数据 | 第10/11章区分“视频表征预训练数据”和“动作条件数据”；核心实验随书提供小型、许可清晰的 fixture，动作条件练习优先使用带 ego-motion/control 的数据或仿真 rollout |

## 1. 书籍定位

### 1.1 一句话定位

一本帮助 CV 工程师从开放环视觉任务迁移到闭环智能系统的开源教材：既解释世界模型与具身策略的基本原理，也用可运行实验检验“模型是否真的有助于行动”。

### 1.2 目标读者

- 熟悉 CNN、ViT/Transformer、分类/检测/分割中的至少一类任务；
- 能阅读 PyTorch 代码并完成常规训练、验证和误差分析；
- 希望进入世界模型、机器人学习、VLA、自动驾驶仿真或 Physical AI 工程；
- 可以没有强化学习、机器人学、控制、物理仿真或 3D 视觉基础；
- 不要求理解多视图几何、点云、NeRF/3DGS 或 occupancy，这些由第3章和第12章补齐。

### 1.3 学完后的可验证能力

读者应当能够：

1. 用统一语言区分世界模型、策略、VLA、视频生成器、仿真器和数字孪生；
2. 从观测、动作、隐状态、转移、奖励/价值和终止条件读懂一个世界模型；
3. 用 S 档实现并审计 RSSM 的 prior/posterior、open-loop/filtering 和 imagined-target 接口；选择 M 档时再训练小型 RSSM，并用于规划或策略学习；
4. 解释行为克隆、ACT、Diffusion Policy、动作 token、flow matching 和 VLA 的联系；
5. 在 S 档统一 action schema 与评测协议下比较至少两类策略输出；选择 M 档时再训练/微调操作策略，不把 GPU 训练作为读完全书的前置；
6. 识别 teacher forcing、复合误差、模型利用、仿真偏差和 benchmark 饱和等常见陷阱；
7. 写出包含假设、基线、资源、种子、置信区间、失败案例和证据等级的实验报告；
8. 为一个具身任务设计数据—训练—评测—部署—回流闭环，并明确安全边界。
9. 从相机坐标、深度和点云开始，理解 occupancy、affordance 与动态空间表征如何服务行动。

### 1.4 本书不是什么

- 不是 ROS、机械设计或控制理论大全；
- 不是只做论文摘要的“模型图鉴”；
- 不是把高画质视频生成自动等同于物理理解；
- 不是承诺在消费级硬件上复现闭源基座模型的指标；
- 不是自动驾驶、人形机器人或三维视觉的百科全书；
- 不用公司演示视频替代可审计实验。

## 2. 全书统一概念框架

### 2.1 贯穿全书的闭环

```text
环境 e_t
  ↓ 传感器
观测 o_t ──编码/状态估计──> 状态或信念 z_t
  ↑                              │
  │                              ├─预测：z_{t+1}, o_{t+1}, r_t, done_t
  │                              ├─反事实：如果执行 a_t 会怎样
  │                              └─决策：规划器 / policy / value / critic
  │                                             │
  └────────────── 环境反馈 <──── 动作 a_t <─────┘
```

本书采用工作定义：

> **世界模型是对环境状态及其随动作演化规律的可学习表示；它必须能够支持预测、反事实推演、规划、策略学习或价值估计中的至少一种用途。**

因此，“能生成未来视频”既不是世界模型的必要条件，也不是充分条件。是否有动作条件、是否保持任务相关状态、是否能改善闭环决策，都比画面逼真度更关键。

### 2.2 四个判断轴

遇到任何新模型，统一回答四组问题：

| 判断轴 | 需要回答的问题 |
| --- | --- |
| 表征 | 显式状态、符号、对象、隐变量、像素/视频、3D 场还是混合表征？ |
| 动力学 | 是否建模动作条件转移、不确定性、奖励/价值、终止与长时序？ |
| 用途 | 用于表征预训练、数据生成、模拟器、规划、策略训练、critic 还是安全验证？ |
| 闭环 | 只做离线预测，还是接受策略动作并经真实/仿真反馈反复更新？ |

### 2.3 相邻概念边界

| 概念 | 最小定义 | 与世界模型的关系 |
| --- | --- | --- |
| 视频生成模型 | 根据上下文生成视频 | 只有在动作可控、状态有用且能支持决策时，才可作为世界模型组件 |
| 物理仿真器 | 由显式规则或数值方法推进环境 | 可以不学习；可提供世界模型训练数据或评测环境 |
| VLA | 将视觉、语言和机器人状态映射为动作 | 本质上是策略；内部不一定包含显式世界模型 |
| 数字孪生 | 与特定真实对象/系统同步的数字表示 | 强调对象身份、校准和同步，不等于通用生成模型 |
| 3D 表征 | 对几何、语义或空间关系的表达 | 可成为世界模型状态，但静态重建本身不含动力学 |
| World-action model | 联合建模世界演化与动作的架构族 | 是研究方向，不作为已有统一定义或已解决范式 |

## 3. 教学设计

### 3.1 两条贯穿实验线

#### 实验线 A：从像素到想象中的控制

```text
Gymnasium / DM Control 小任务
→ 观测与状态基线
→ VAE / 离散表征
→ RSSM
→ CEM 规划
→ Dreamer-lite
→ 开环预测与闭环回报对照
```

目的：用小系统把“学模型—用模型—被模型误导”的全过程讲透。默认不追求论文原始规模。

#### 实验线 B：从示范数据到机器人策略闭环

```text
LeRobot 数据格式
→ 行为克隆 / ACT
→ Diffusion Policy 或 SmolVLA
→ LIBERO / RoboCasa 小任务评测
→ 微调或简化后训练
→ 延迟、失败恢复和安全门控
```

目的：让读者体验数据规范、动作表示、闭环评测和部署约束。OpenVLA、OpenPI、GR00T 作为进阶替换，不作为入门必跑依赖。

### 3.2 资源档位

| 档位 | 典型资源 | 内容承诺 |
| --- | --- | --- |
| S：最小实验 | CPU / Apple Silicon / 8–12GB 显存 | 30 分钟内完成 smoke、推理或指标计算 |
| M：标准实验 | 单卡 16–24GB，2–8 小时 | 小数据训练、LoRA/小模型微调、20–50 episode 评测 |
| L1：单卡扩展 | 单卡 24GB，8 小时–3 天 | 梯度累积、LoRA、较长评测或轻量后训练 |
| L2：研究验证 | 最多 2×80GB，1–3 天以上 | 大模型、RL 后训练、视频世界模型的选做实验 |

正文必须保证 S 档可完成核心理解，必做训练不得超过 24GB 单卡。L2 只用于少数明确标为
“研究扩展”的选做实验，不得成为理解后续章节的前置条件。任何超过 2×80GB 的实验只介绍
方法与公开结果，除非作者另行批准。不得把 A100/H100 上的结果写成“消费级可复现”。

S/M/L 只描述本地计算资源，不覆盖全部复现成本。每张实验卡还必须独立记录：CPU 与内存、峰值显存、磁盘占用、下载量、数据准备时间、训练与评测时长。涉及闭源 API 时，另记模型快照、请求数、费用、端到端延迟、限流、网络依赖和数据治理要求；不得用“不占本地显存”代替资源预算。

### 3.3 三条阅读路径

| 路径 | 必读章节 | 适用目标 |
| --- | --- | --- |
| 世界模型 / 决策 | 1–10 → 17–18 → 20 → 22 | 模型式 RL、世界模型、规划、仿真 |
| VLA / 操作策略 | 1–4 → 13–21 → 22 | 机械臂、通用策略、VLA 训练与部署 |
| 自动驾驶 / 空间智能 | 1–4 → 9–12 → 17 → 19–22 | 场景生成、occupancy、闭环评测、系统工程 |

### 3.4 零基础 3D 桥接门

第3章结束时安排一个 4–6 小时的桥接单元，不要求多视图几何先修，但读者必须能够：

1. 解释像素、相机、车体/机器人和世界坐标系的区别；
2. 用内外参完成像素反投影与坐标变换，并通过可视化检查轴向和尺度；
3. 将一个小型 RGB-D 样例转换为点云；
4. 将点云栅格化为简化 occupancy/BEV，并识别遮挡与视野外区域；
5. 在合成样例中定位轴向、单位、时间同步和外参扰动造成的错误。

桥接单元提供不依赖受限数据集的微型 fixture、参考输出和自动检查。通过后再进入第12章；没有通过的读者仍可继续世界模型或 VLA 路径，但第12章实验不应默认其已掌握这些操作。

### 3.5 默认仿真与实验环境

| 层级 | 默认选择 | 选择理由 |
| --- | --- | --- |
| 基础控制与世界模型 | Gymnasium / DM Control + MuJoCo | 接口稳定，适合 RSSM、MPC 与 Dreamer |
| 机器人操作主线 | MuJoCo + robosuite/LIBERO | 衔接 ACT、VLA、后训练和主流评测 |
| 机器人操作加速后端（M/L1 档可选） | MuJoCo MJX-JAX 或 MJX-Warp | 沿用 MuJoCo 模型体系并加速批量 rollout；两种实现的功能、自动微分、碰撞和性能边界不同，实验卡必须明确实现与版本 |
| 数据与策略接口 | LeRobot | 统一 trajectory 数据、策略训练、评测和可选硬件接入 |
| 复杂日常操作 | RoboCasa | 作为第16、19、20章的进阶多任务扩展，不是冷启动依赖 |
| GPU 并行与高保真传感器 | Isaac Lab | 作为 L2 扩展；安装和渲染链路较重，不作为全书默认环境 |
| 自动驾驶闭环（S/M 档默认） | MetaDrive 内置程序化场景 | 轻量、可 CPU 运行、支持点云/RGB/BEV 观测，不要求下载有额外许可的真实驾驶日志；用于第19–22章的默认闭环规划评测 |
| 自动驾驶感知与高保真闭环（L2 档选做） | CARLA（含录制数据）+ 公开驾驶视频数据集 | 覆盖 MetaDrive 程序化渲染无法满足的多相机真实纹理、BEV/occupancy 感知练习；S/M 档优先使用录制数据和预生成场景 |

MuJoCo 是本书默认物理引擎，LIBERO 是默认机器人操作 benchmark。MJX 是可选硬件加速实现，但不假设其与 C MuJoCo 数值等价；切换前必须检查任务所需功能，并在固定动作序列上比较状态、接触、终止和回报偏差。MetaDrive 是自动驾驶闭环评测的 S/M 档默认项，负责规划、决策和安全指标；CARLA 保留为高保真感知与闭环的 L2 档选做项，考虑其 UE5 路线的显存和磁盘要求，不要求所有读者安装。两者分工：MetaDrive 管“决策评测”，CARLA/录制数据管“感知真实性”。每个仿真实验必须锁定引擎、实现、任务、资产、控制器和渲染后端版本；接入 ScenarioNet、Waymo、nuPlan 或 nuScenes 时另行核验源数据许可。

## 5. 章节详细设计

本节的实验描述以当前仓库为准，固定拆成两层：**S 档（已交付）**是零下载或微型数据、CPU/Docker 可验证的教学合同；**M/L 档（可选待验证）**才包含真实数据、上游 checkpoint、训练或仿真。S 档负责证明接口、算术、反例和失败路径，不冒充模型性能；M/L 档没有真实运行前必须保持 `pending`。这种拆分是交付状态，不降低章节最终研究目标。

### 第一部分：从视觉识别到闭环智能

#### 第1章 从“看见”到“行动”

- 核心问题：为什么静态识别指标不能代表具身能力？
- 内容：闭环反馈、部分可观测性、分布偏移、动作改变未来观测、实时性与安全。
- CV 桥接：把 dataset shift 扩展为 policy-induced distribution shift。
- S 档（已交付，`EXP-01-01` v3）：两条逐步 MAE 相同的手工 residual 序列产生不同积分状态和安全边界结局；同一持续扰动再比较无反馈、及时反馈、两步观测延迟与动作权限不足，显式报告越界和饱和；另以相同扰动 multiset、平均绝对值和终态的重排序列得到0.3/0.476不同瞬态峰值，阻止用最终恢复覆盖中途越界。
- M 档（可选待验证）：把同一感知误差注入小型仿真控制器，比较离线指标与闭环轨迹；不要求实体硬件。
- 双案例：机械臂抓取与自动驾驶分别展示动作如何改变后续观测分布。
- 产出：全书闭环地图和个人学习路径。

#### 第2章 世界模型到底是什么

- 内容：状态、信念、转移、观测、奖励、continuation；生成式与非生成式；显式与隐式；学习模型与物理仿真器。
- 关键对照：model-free policy、VLA、video predictor、digital twin、world model。
- S 档（已交付，`EXP-02-01` v4）：为 8 个代表系统填写四轴系统卡，显式区分转移、动作干预、学习动力学与直接策略输出，并用两 context 的 state-aliasing 反例检查任务相关状态是否合并不同最优动作；不训练大模型。
- M 档（可选待验证）：锁定上游版本后运行最小官方入口，核对系统卡中的资产与接口声明；不把安装成功当作能力验证。
- 产出：一页式术语契约，后续章节不得重新发明定义。

#### 第3章 具身任务的最小机器人学与决策基础

- 内容：相机模型、坐标变换、投影/反投影、深度与点云直觉；SE(3)、正/逆运动学、车辆/关节/末端动作、控制频率、MDP/POMDP、规划与策略。
- 边界：只讲理解学习系统所需的最小控制知识；系统性推导链接到 Modern Robotics 和 MIT Robotic Manipulation。
- S 档（已交付，`EXP-03-01`）：三像素 RGB-D 完成投影/反投影、optical→body→world 变换链与尺度/轴向反例；单点解析运动夹具把 100 ms 位姿错位量化为平移/转动空间误差；二维机械臂用固定执行偏差比较开环和反馈。
- M 档（可选待验证）：加入真实或合法再分发的标定、畸变、噪声和时间错位样例；实体相机与机械臂不作为必需条件。
- 产出：观测/状态/动作 schema。

#### 第4章 数据、基线与实验协议

- 内容：trajectory/episode、示范数据、离线数据、仿真数据、时间同步、归一化、train/eval 泄漏、随机种子和置信区间。
- S 档（已交付，`EXP-04-01`）：审计程序化多传感器 episode metadata，覆盖结束语义、时间戳、缺帧 mask、动作范围、归一化作用域，以及跨 split 的 group、原始来源、精确内容指纹和预登记近重复簇；当前检出 11 类注入问题，但不读取媒体或自动发现语义近重复。
- M 档（可选待验证）：在获得许可后审计 LeRobot 或驾驶数据的真实视频解码、clock domain、标定、隐私、许可与 route/scene 切分。
- 自动驾驶案例：检查多相机/车辆状态/地图时序对齐，并按 route/scene 而不是相邻帧做切分。
- 产出：`experiment-card.json`，记录主张、资源、数据、基线、指标、种子和停止条件，并通过统一 Schema 校验。

### 第二部分：学习一个可用于决策的世界

#### 第5章 预测模型的生成式基础

- 内容：VAE、离散 latent、序列模型、扩散/流匹配、masked prediction；只保留后续会复用的机制。
- 重点：重建损失、预测损失与任务相关表示之间并不等价。
- S 档（已交付，`EXP-05-01` v4）：用解析多峰标量 future 区分条件忽略、mode collapse、support 外生成和点均值落在 support 外，并核对 diffusion/flow 路径端点；三成员 range 负对照另证明高分歧可触发拒绝，但相关成员共同犯错时低 disagreement 不代表正确；加入高分歧但均值正确的 case 后，阈值0/0.25/2的 coverage 为0.25/0.5/1、接受 failure rate 为1/0.5/0.5，表明收紧 gate 不保证降低观察风险。四例均为手工点，不代表校准、总体 OOD 风险或安全收益。
- M 档（可选待验证）：在小型许可数据上比较像素重建、latent prediction、条件 NLL 与下游 probe；不以大型图像生成训练为前置。
- 不做：完整图像生成教材或大型 DiT 训练。

#### 第6章 World Models 与循环状态空间模型

- 锚点：Ha & Schmidhuber 的 World Models；RSSM 的确定性/随机状态组合；DreamerV3（现已发表于 *Nature*，2025）。
- 内容：编码、转移、解码、奖励与 continuation；teacher forcing 与自由 rollout。
- 前瞻链接：本章的 RSSM 是第8章 Dreamer 系列（含 Dreamer 4 的因果 tokenizer + shortcut forcing）的必要基础，先讲清楚状态而不是提前讲想象训练。
- S 档（已交付，`EXP-06-01`）：`BENCH-06-01` v3 以一维部分可观测轨迹分离 posterior filtering、从每个 posterior 历史出发的一步 prior 与初始化后不重置的 open-loop，并登记 h1/h4/h8/h16/h31；未来观测统一 `+1` 的负对照只允许观测消费分支变化，open-loop 必须精确不变。另冻结两组 categorical posterior/prior、KL 方向、Dreamer 式 stop-gradient 目标标签、free-nats 阈值与 dyn/rep scale，明确单 seed 标准库算术不验证真实梯度、posterior leakage 频率、规划性能或神经训练。
- M 档（可选待验证）：实现或锁定 mini-RSSM，在小型控制任务比较 one-step、multi-step 与闭环指标；24GB 配方只有实测后才能发布。
- 产出：全书第一个真正可用于反事实 rollout 的模型。

#### 第7章 用模型做规划：从 PlaNet 到价值等价模型

- 内容：CEM/MPC、latent planning、uncertainty、MuZero 式 value-equivalent 思路。
- S 档（已交付，`EXP-07-01`）：v4 穷举三状态延迟回报任务，验证 horizon、terminal value、固定动作预算的扰动后重规划、环境 reward 与 bootstrap value 分账、受限 value equivalence，以及均值/经验下尾/chance constraint 排序反转；非整数 `αN` 的经验下尾按分位点边界质量计权，`ceil(αN)` 只保留为扩大实际尾部比例的粗略负对照；不等动作预算结果只保留为 protocol negative control。
- M 档（可选待验证）：固定 learned world model，用 CEM 与 random shooting、无规划/无模型基线比较，同时报告候选预算、墙钟、model/real return gap 和 seed。
- 重点：模型不必重建所有像素，但必须保留决策相关信息。

#### 第8章 在想象中学习：Dreamer 系列

- 内容：imagined rollout、actor-critic、离散 latent、跨域鲁棒性；区分论文与公开重实现。
- 谱系更新：DreamerV3（论文 `[P]`，官方/作者资产单独审计）→ Dreamer 4（Hafner, Yan & Lillicrap，2025-09，论文 `[A]`）。Dreamer 4 用因果 tokenizer 和 shortcut forcing 实现单 GPU 实时交互推理；这不能外推为完整训练可在 24GB 单卡完成，截至核查日期的核心验证也以 Minecraft 类任务为主，不代表机器人操作闭环已解决。
- S 档（已交付，`EXP-08-01`）：v4 用手工 reward/discount/continuation/value/loss 序列核对 λ-return、reward bias、终止后泄漏、terminated/truncated bootstrap、截断处 bootstrap discount 与跨 episode λ-trace mask 的双信号边界，以及累计 survival weight 是否屏蔽终止后的伪 actor/critic loss。
- M/L 档（可选待验证）：以本书 mini-RSSM/Dreamer-lite 或经过资源审计的 DreamerV3 debug 配置为主；Dreamer 4 社区 PyTorch 实现只作为 M/L1 选做，必须锁定提交、数据和配置，并先实测峰值显存、耗时、收敛与官方主张的对应关系。
- 产出：模型学习误差如何进入策略梯度的因果图；主实验比较 Dreamer-lite 与无模型/随机基线。DreamerV3 与 Dreamer 4 的横向表只报告已核验的速度、稳定性和样本效率，不用推理速度替代训练成本。

#### 第9章 世界模型如何评测与失败

- 内容：one-step/multi-step、FVD/LPIPS 等感知指标、latent probing、物理一致性、可控性、规划回报、真实闭环效用。
- 元讨论：评测本身应该评测什么？引入“以决策效用为中心”的评测立场之争，说明视觉质量榜单和决策效用榜单是两套不同的证据，不能互相替代。
- 案例基准：WorldArena v1 分别评估视频感知质量、合成数据、策略评估、动作规划和人工评价，数据基础是 RoboTwin 2.0 仿真子集；WorldArena 2.0 作为独立案例卡核验，不把不同版本合并概括为已经覆盖触觉或仿真—真实全链路。
- 失效模式：复合误差、幻觉、模型利用、遗漏变量、因果混淆、奖励误设、OOD 动作；“幻觉可预测且可预防”作为预印本案例，只说明其特定模型与数据覆盖条件下的量化结果，不写成适用于所有世界模型的普遍定理。
- S 档（已交付，`EXP-09-01`）：一维动作干预与目标到达 fixture 构造 one-step error 与闭环排序反转，并展示 rollout 缺失时 available-case 与固定分母排序反转；四行二元概率表再证明粗分箱 ECE 可把无信息 base-rate 与 informative forecast 同记为零，必须并列 proper score、分箱协议与概率分辨率。
- M 档（可选待验证）：在锁定的视频/latent predictor 和闭环环境上构造“画面更好但控制更差”对照，报告逐 horizon coverage、动作敏感度和真实 outcome。
- 自动驾驶案例：对比视频质量、轨迹碰撞率、路线完成率和稀有事件覆盖率，说明开环指标不能替代闭环评测。
- 产出：世界模型 benchmark card；这是后续所有新模型的准入门槛。

### 第三部分：可扩展的世界表征

#### 第10章 非生成式预测表示：I-JEPA 到 V-JEPA 2.x

- 内容：目标编码器、上下文编码器、masking、latent prediction、视频预训练与动作条件适配。
- 讨论：非生成式表示更适合哪些任务，又缺失哪些可解释的未来细节？
- 数据锚点：Ego4D、EPIC-KITCHENS 作为需要遵守各自许可与获取流程的第一人称视频数据，用于 probing 和轻量 masked predictor 的训练/微调；明确它们只是数据来源，不代表某个基准分数可直接外推到本书任务。核心实验不得要求下载 TB 级完整数据。
- S 档（已交付，`EXP-10-01`）：手工 task/texture 表征 fixture 比较 reconstruction、ID probe、锁定 nuisance shift、时间方向/反转敏感度和动作条件反事实，含 collapsed、middle-frame 与 action-blind negative control；不下载官方 checkpoint。
- M 档（可选待验证）：在许可允许时调用锁定的 V-JEPA 2.x 特征做 probing，或在小型数据子集训练轻量 masked predictor，并报告下载量、磁盘占用、预处理时间和 shift split。
- 边界：不能从表征 benchmark 直接推出通用物理理解。

#### 第11章 动作条件视频世界模型

- 内容：latent action、action-conditioned video、长时序一致性、交互速度、可控性；Genie 系列（Genie 3 已从研究预览开放为 Project Genie 产品）、GameNGen、机器人/自动驾驶视频模型作为案例。
- 数据锚点：OpenDV 一类驾驶视频数据可用于视频预测预训练，但其视频/语言标注不默认包含可直接监督控制的动作。动作条件练习优先使用带 ego-motion、轨迹或控制量的数据，或由 MetaDrive/CARLA 生成带版本记录的 rollout；数据开放不代表对应模型结果可复现。
- 自动驾驶闭源案例：Wayve GAIA-1→4（从驾驶视频生成、可控场景到闭环策略评测）、Waymo 基于 Genie 3 构建的专用驾驶世界模型；均标注 `[V,R0]` 或 `[V,R1]`，只用于讨论架构与用途边界，不安排复现。GAIA-4 是截至 2026-08-31 的最新供应商案例，后续版本进入案例卡而不改变稳定章节结构。
- 核心对照：renderer、simulator、planner 三种用途，不把高保真 renderer 自动叫作 simulator——Genie 3 这类通用交互世界模型和 GAIA 这类领域专用驾驶世界模型正好构成这组对照的两端。
- S 档（已交付，`EXP-11-01`）：四动作网格转移表比较 action-blind、action-conditioned 与左右语义交换模型，测试未见动作组合、counterfactual 方向、全轨迹分母与终点误差抵消假阴性。
- M 档（可选待验证）：训练小型 action-conditioned frame/video predictor，测试未见动作序列；驾驶支线只使用带 ego-motion/control 的合法数据或仿真 rollout 比较转向/制动条件未来。
- 边界：闭源研究预览只做案例卡，不安排“复现”。

#### 第12章 可行动的空间表征

- 零基础入口：先用图示和代码补齐相机内外参、深度、点云、体素、BEV 与坐标变换，不假设读者学过多视图几何。
- 内容：对象与关系、深度/点云、NeRF/3DGS、occupancy、scene graph、affordance、动态 3D 表征。
- 教学组织：从“重建得像”转向“是否支持碰撞、抓取、导航和状态跟踪”。
- S 档（已交付，`EXP-12-01`）：三条无噪深度射线构造 7×7 三态 BEV，测试半开米制栅格的原点/分辨率/负边界、类别不平衡与 observed mask、遮挡未知、动态清空证据、稀疏 waypoint 间的 Bresenham 路径段、footprint、证据过期和一格坐标偏移；不把固定索引、离散栅格化称为外部地图实现或连续碰撞检测。
- M 档（可选待验证）：从合法 RGB-D/点云构造 occupancy 与可抓取区域；驾驶支线使用录制数据或仿真构造 BEV occupancy，加入动态对象、坐标和时间误差。
- 案例：Occ3D/OpenScene 等自动驾驶 occupancy 与动态场景、机器人 real-to-sim 场景构建、NeRF/3DGS 三维重建；D4RT 作为 2026 年动态 4D 重建/跟踪案例 `[V/A,R0]`，只讨论从重建到行动接口的缺口，不把官方演示当作任务复现。

### 第四部分：从示范到通用动作策略

#### 第13章 模仿学习、误差累积与动作分块

- 内容：behavior cloning、DAgger 直觉、ACT/ALOHA、chunk size、temporal ensembling。
- S 档（已交付，`EXP-13-01`）：v4 用单点 expert support 上同为零 action MSE、扰动 rollout 相反的手写反馈规则拆开离线拟合与支持集外行为；无反馈标量积分器另以相同 RMSE/MAE、不同时间相关性的误差对照揭示逐点指标缺口，扰动时序和重叠 chunk fixture 展示 prediction/execution horizon 取舍与 temporal ensemble 降抖—滞后反例。
- M 档（可选待验证）：在许可明确的小型 LeRobot 任务训练 BC 与 ACT，对比开环误差、闭环成功、执行时域、查询次数和尾延迟。
- 产出：第一份策略失败轨迹分类。

#### 第14章 生成动作：Diffusion Policy 与 Flow Matching

- 内容：多峰动作分布、条件去噪、receding horizon、flow matching；与图像生成的相同点和不同点。
- S 档（已交付，`EXP-14-01`）：v4 解析双峰标量动作比较条件均值、迭代 mode refinement、oracle straight flow，并用相同有效率/覆盖、不同模式频率的负对照补齐 frequency diagnostic；再以单候选边际接受率同为20%的 iid/完全相关端点拆开 best-of-N 与候选依赖结构，另含候选—batch 预算、独立场景安全筛选和 deterministic fallback。
- M 档（可选待验证）：在 Push-T 或 LIBERO 小任务比较 MSE、diffusion 和 flow policy，统一数据、候选数、solver steps、execution horizon、P95 时延与闭环协议。
- 重点：推理步数、动作 horizon、控制频率和延迟共同决定真实效果。
- 自动驾驶支线：把保持车道、变道与减速建模为多峰轨迹候选；统一报告轨迹 frame、prediction/execution horizon、模型调用数、P95 时延、约束违反与闭环碰撞，所有候选经过独立安全筛选。

#### 第15章 VLA 的架构模式

- 内容：视觉编码器 + 语言模型 + 动作头；离散动作 token、连续动作、FAST、扩散/flow action expert、双系统与分层策略。
- 代表案例：RT-1/RT-2、OpenVLA、π 系列、SmolVLA、GR00T；按架构模式而非版本号组织。
- 最新活页案例：截至 2026-08-31，Isaac GR00T 官方主分支为 N1.7，采用更新后的 VLM 主干与连续 flow-matching action head；版本号、动作维度、horizon 和上游性能只进入案例卡 `[O,R1]`，不改写稳定的“双系统 + action expert”章节骨架。
- 基线对照：可选用版本锁定的商用通用 VLM API 做零样本/少样本提示控制。供应商能力声明默认标注 `[V,R0]`；只有保存模型快照、请求与响应、参数、日期、费用和重试记录的具体实验才可标 `[V,R1]`。它是“未经动作微调的闭源提示基线”，不是预设的性能下界，也不是必做依赖。
- S 档（已交付，`EXP-15-01`）：v4 手工 continuous/token/flow action packet 解码到同一版本化 schema，并用观测/首动作 timestep 揭示“生成时间新鲜不等于 step 对齐”，再用完整 `action_timesteps` 拒绝首步正确但后续重复/跳步的 chunk；共拒绝 horizon 越权、step 错位、replay、乱序、错误 clock、字段顺序等14类合同错误。
- M 档（可选待验证）：SmolVLA 或 OpenVLA 小规模微调/推理可与版本锁定 VLM API 在同一协议下对比；统一输入、动作反归一化并报告成功率、延迟、费用、限流和失败重试。没有凭证时使用已归档响应或本地规则基线，不阻塞主线。
- 边界：VLA 是策略，不因含有大模型就自动具备可验证的世界模型。VLM API 只输出低频、高层候选动作，必须经过动作范围、时序、碰撞与安全门控，不能直接连接高频执行器；实验目的在于测量差异，而不是预先证明通用模型更差。

#### 第16章 数据规模化、跨本体迁移与高效适配

- 内容：Open X-Embodiment/DROID/LeRobot 数据组织、动作空间对齐、跨机器人归一化、LoRA/OFT、蒸馏、异步动作执行。
- S 档（已交付，`EXP-16-01`）：v4 两种 equal-shape 机械臂动作用版本化 adapter 对齐单位和夹爪极性，比较 naive raw pooling，并用 schema fingerprint 拒绝缺失/陈旧合同；另以2个来源、4个 episode、14个 transition 拆开 dataset/episode/transition-uniform 的期望暴露，并用三步 drop-tail action window 证明 short 来源可从14.2857% raw-transition 暴露降为0个合格窗口。
- M 档（可选待验证）：同一 learned policy 在两个任务/本体 schema 上做 adapter，按 seen/few-shot/zero-shot 切分记录负迁移、数据质量、时延和闭环 outcome。
- 工程重点：license、数据来源、checkpoint 兼容、预处理与部署协议都属于模型的一部分。
- 自动驾驶支线：跨车队日志不得直接混合同名 raw control；优先转换到 ego-frame 时间轨迹或 fleet-specific adapter，并按车辆/路线拆分报告迁移矩阵、时延、隐私与许可。

### 第五部分：世界模型与策略融合

#### 第17章 世界模型帮助策略的五种方式

- 统一框架：
  1. 表征预训练；
  2. 合成/扩充训练数据；
  3. 作为可交互模拟器；
  4. 用于规划、奖励或 critic；
  5. 用于安全预测和反事实验证。
- 第六种用法需要单独警惕：**把世界模型当作真实评测的低成本替身**（用神经模拟器复现真实机器人评测榜单排序）。这类工作证明了排序相关性，但排序相关不等于绝对数值可信；正文把它作为“世界模型用途”里风险最高的一种单列讨论，不与前五种并列展示。
- 案例：Dreamer、V-JEPA-AC、world-model-based VLA fine-tuning、Cosmos 类平台；统一/异步 latent action 世界模型（如把多机器人 embodiment 映射到统一动作空间的新架构）作为“表征预训练+可交互模拟器”交叉用途的案例。
- 自动驾驶案例：世界模型分别承担场景生成、驾驶 rollout、规划代价估计和稀有事件验证；四种用途的证据不能混用。
- S 档（已交付，`EXP-17-01`）：v6 手工 safe-route/phantom-shortcut 转移展示 8/9 转移一致仍可导致策略错排与 model exploitation；两套 support 声明验证 gate 能拒绝 coverage 外捷径，却不能发现同一 coverage 内模型错误；另用两个同为8/9正确的单故障模型证明，错误位于当前候选可达 query 或未访问 query 会产生1.85/0的不同 regret。
- M 档（可选待验证）：固定策略，在版本锁定的物理/驾驶仿真器与 learned world model 中分别 rollout，量化 transition、return、ranking、coverage 和 policy exploitation gap。
- 产出：“世界模型有用”必须对应到可测量下游效用，不能只展示生成视频。

#### 第18章 VLA 后训练、长时序与 World-Action Models

- 内容：SFT 后的在线/离线 RL、人类纠正、稀疏奖励、world-model rollout、critic、层级任务与记忆。
- 最新方法簇：RIPT-VLA、VLA-RFT、WoVR/World-Gymnast 等作为研究案例；以方法假设和失效条件分类，不承诺复现全部论文。
- S 档（已交付，`EXP-18-01`）：v4 四条手工两阶段轨迹复现离线奖励重加权、ESS/recovery trade-off、marginal support 假阳性和 RLOO 全同奖励退化；另以四个 easy/medium/hard context 组显式拆开 dynamic rejection 的 attempted、rejected 与 used 分布，并用相同 used batch、不同 rejected 历史证明 optimizer 输入不能恢复尝试成本与 coverage。
- M/L 档（可选待验证）：在 LIBERO 上做不同规模的小步后训练，对比 SFT 基线、真实 simulator 与 learned simulator；先锁定数据、policy、reward、group sampling 和资源停止条件。
- 风险：世界模型误差会污染奖励和优势估计，策略可能主动利用模型漏洞。
- 术语边界：World-Action Model 是研究趋势标签，正文给出多个实现路径而不是单一定义。

### 第六部分：走向真实系统

#### 第19章 物理仿真、Real2Sim 与 Sim2Real

- 内容：MuJoCo/LIBERO 主线，RoboCasa、Isaac Lab 进阶；域随机化、系统辨识、传感器/执行器延迟、接触与摩擦、Real2Sim2Real。
- 加速选项：M/L1 档可切换到 MuJoCo MJX-JAX 或 MJX-Warp 以获得更大批量 rollout 吞吐。实验必须记录实现、版本和不支持功能，并用固定动作序列对照 C MuJoCo 的状态、接触、终止与回报；只有偏差在任务容忍范围内，才进行样本效率比较。
- S 档（已交付，`EXP-19-01`）：v4 标量校准 fixture 注入 dynamics、delay 与 observation scale gap，展示 observation-only 的结构不可辨识性、state anchor、多工况信息增量，以及相同逐维边际但不同联合配对的有限 domain-randomization support。
- M/L 档（可选待验证）：先在 MuJoCo 建立可校准 pick-and-place 或在 MetaDrive 建立程序化驾驶场景，再逐项注入视觉、动力学和延迟偏差；需要真实纹理时才升级 CARLA/录制数据。
- 自动驾驶支线：S/M 档默认用 MetaDrive 做闭环规划评测（轻量、可 CPU 运行），并注入天气、交通参与者、传感器噪声与车辆动力学扰动；需要高保真多相机纹理或 BEV/occupancy 感知练习时，切换到 CARLA 的录制数据或选做闭环环境；两者不互相替代，区分场景多样性和真实有效性。
- 重点：仿真可重复不等于仿真有效；必须报告资产、引擎、控制器和参数版本。

#### 第20章 具身评测：从成功率到部署证据

- 内容：LIBERO、SimplerEnv、RoboCasa、MetaDrive 与 CARLA 等 benchmark 的目标和盲区；任务成功、路线完成、碰撞、时间、干预、鲁棒性、安全、能耗与恢复能力。
- 基线对照：可把第15章的版本锁定 VLM API 基线接入同一评测协议，量化闭源提示模型与动作微调策略之间的成功率、控制频率、端到端延迟、费用和失效类型；不要求读者购买 API 额度，且所有动作经过独立安全层。
- 2025–2026 评测生态案例：分布式真实机器人评测榜单（众包用户在真实场景中评测通用策略）、可与真实榜单排序高度对齐的高保真仿真/神经模拟评测平台、Real2Sim2Real 场景重建评测（如基于 3D Gaussian Splatting 的仿真器）。这批工作共同印证一个既有论断：仿真结果可以与真实排序强相关，但不能替代真实数值；正文只引用其排序相关性证据，不外推具体成功率。
- 协议：任务切分、episode 数、失败定义、配对 joint outcome、置信区间、checkpoint 选择、仿真与实机相关性。
- S 档（已交付，`EXP-20-01`）：v11 八 episode 2×2 表改变任务总体和 success rule，显式保留 truncated、拒绝 technical-invalid 聚合，并展示协议交互与 Wilson 区间假设；4 task/6 attempt 的失败后重试 ledger 拆开 first-attempt、per-attempt、task-with-up-to-two-attempts 与平均成本；另用十对结果/四条不平衡 route 区分 episode-micro、等 route macro 和 paired cluster bootstrap 的 estimand 与边界，再用两张相同边际成功率、不同 discordant cells 的20对表证明边际差不能恢复配对不确定性；零事件审计先给独立 Bernoulli 上界，再以十条 route×十次 replay 证明重复成员不会创造独立 route，且 per-episode event 与 per-new-route incidence 是不同 estimand；四 checkpoint×三 split 手工表把 selection、一次性 final 与 untouched confirmation 角色分开，用负对照阻止看完 final 再挑 checkpoint 后仍声称独立评测。
- M 档（可选待验证）：用同一冻结模型在两种预注册评测设置下运行，保留逐 episode 记录、cluster/paired 结构与失败视频，解释数字何时不可横比。
- 产出：可发布的 benchmark card 和失败视频索引。

#### 第21章 部署、实时性与安全边界

- 内容：传感器同步、policy server、动作队列、异步推理、量化/蒸馏、watchdog、fallback controller、人工接管、日志与回放。
- 安全原则：模型输出不能绕过动作范围、碰撞检查、速度/力限制和急停；高风险动作必须进入独立 safety layer。
- S 档（已交付，`EXP-21-01`）：手工 latency burst、action packet、async chunk 与 fallback state machine 注入超时、陈旧观测、异常动作、queue underflow 和 uncertainty gate 失败；第15/21章共用唯一 `mobile-base-v1` schema，按物理字段登记范围、单位和教学单步变化限值，相邻步负对照保持两个当前动作都在静态范围内，只改变相对上一条手工“已执行”动作的线速度变化，并在历史、schema、单位、频率、ack、producer session 或 executor boot 错配时 fail closed；同 epoch command ledger 让完全重复命令返回缓存回执，分别拒绝同 ID 改 payload、倒序和 epoch 错配，只有显式新 session/boot 后才允许命令号归零；恢复 ledger 结构校验另拒绝布尔 command ID、非有限 action、负 step、畸形 digest 和 digest 与缓存字段不一致；用成对负对照把连续健康窗口与显式 policy-reactivation authorization 分开，再用 `requested/operating/succeeded/failed` 生命周期拒绝未完成、超时或失败后的重新激活；九例 receipt audit 约束 run/target/声明 approver、半开有效期、决定、单调序号与单次消费；严重度负对照保持 coverage、失败率和计数召回相同，只交换被接受的 authored low/high-consequence failure。所有动作、步号、ack、epoch、状态、授权与 `1/10` 敏感性分析代理权重均为手工 fixture；内存 ledger 结构校验不代表存储完整性，且不提供 durable transaction、崩溃恢复、并发线性化、可信执行反馈、物理 exactly-once、真实动力学/jerk、真实后果、fallback 完成检查、身份认证、完整性保护或真实授权链。
- M 档（可选待验证）：在版本锁定的仿真或 ROS-like 容器内注入相机冻结、服务断连、规划超时与执行越界，测量真实墙钟、watchdog、fallback 完成/失败和恢复。
- 自动驾驶支线：加入定位漂移、传感器掉线、规划超时、控制越界和最小风险停车；不把神经网络策略直接连接执行器。
- 产出：从模型 checkpoint 到机器人执行器的时序图和故障契约。

### 第七部分：综合项目与持续研究

#### 第22章 端到端综合项目：一个可审计的具身研究闭环

- 读者从以下课题选择一个：
  - 世界模型用于 MPC；

  - learned simulator 用于策略后训练；
  - 3D/occupancy 表征用于抓取或导航。
  - 驾驶世界模型用于反事实场景生成、规划或闭环评测。
- 必交物：研究问题、相关工作矩阵、最小基线、实验卡、代码、环境锁、结果表、失败样例、复现命令、模型卡和局限。
- 研究雷达：用“问题—假设—证据—资产开放度—复现成本”追踪新工作，不按公司新闻流追版本。
- S 档（已交付，`EXP-22-01` v5）：审计两个内存 project package，实际执行受限 `python3` probe，区分 stdout digest 漂移与非零退出，并以 authored receipt 绑定 command/result artifact；同时验证五段跨章 trace、artifact digest/producer/claim binding，train/selection/eval 在 group、raw source、精确内容和预登记近重复簇四个维度的隔离，以及评测冻结、资源档位和 safety gateway。probe 不遍历真实项目或运行模型，receipt 未签名，不构成真实结果复现。
- M/L 档（可选待验证）：从五类选题中完成一个真实项目；模型、数据、仿真与硬件均按授权和资源逐级升级，不改变 S 档作为必做出口。
- 附录：100 小时学习计划、CV→具身术语表、数学补充、硬件与数据选型、论文阅读清单。

## 6. 统一章节模板

每章必须回答“为什么、是什么、怎样验证、何时失效”，固定包含：

1. 本章问题与先修知识；
2. 放回闭环地图中的位置；
3. CV 背景桥接；
4. 核心概念与不超过 3 个关键公式；
5. 代表方法谱系，而不是模型名堆叠；
6. 最小实验（S）、标准实验（M/L1）与研究扩展（L2）；
7. 复现范围声明和资源预算；
8. 指标、基线、种子与验收命令；
9. 论文结果、本书结果和未验证声明的分栏对照；
10. 失败模式、适用边界和安全提示；
11. 小结、练习、延伸阅读与下一章接口。

工具型章节可以减少论文精读，但不能省略实验协议和失败边界。

## 7. 证据、引用与时效规则

### 7.1 二维证据标注

不要再用一个颜色把来源质量和复现程度混在一起。正文采用两个标签：

#### 来源成熟度

- `P`：同行评审论文；
- `A`：预印本/完整研究报告，尚未同行评审；
- `O`：官方代码、模型卡、数据卡或基准文档；
- `V`：公司博客、产品页、演示或发布会；
- `T`：第三方分析、新闻或社区整理。

#### 可复现状态

- `R0`：只有声明或演示；
- `R1`：公开部分资产；
- `R2`：官方命令可运行；
- `R3`：存在独立复现/跨团队验证；
- `R4`：本书在锁定环境下复现并公开日志。

示例：一篇带代码但未同行评审的工作可标为 `[A,R2]`；一个经过同行评审但无公开资产的结果可标为 `[P,R0]`。`R4` 只表示本书验证过指定主张，不意味着完整复现论文。

### 7.2 声明最小记录

对性能、规模、实时性、泛化和商业部署相关声明，必须记录：

```text
声明 | 来源 | 发布/核验日期 | 任务与基线 | 资产开放度 | 本书是否复现 | 限制
```

### 7.3 稳定正文与活页内容

- 正文：概念、公式、方法族、经典论文、稳定实验；
- 在线案例卡：模型版本、产品能力、产业新闻和排行榜；
- `reviews/` 中按日期保存候选新工作与快速演进来源审查，未审查前不得进入正文；
- `fact-evidence.json`、`inference-evidence.json` 与关键建议登记表保存机器可读证据合同，章节审查记录解释人工判断；
- 以 GitHub 官方源码支持具体实现事实时，正文和机器证据使用完整 commit 的不可变 URL；`main`、仓库首页或仅按日期记录的快照只能作为发现入口，不能单独支撑稳定事实；
- 每个正式版本明确资料截止日期，过期版本不静默改写。

## 8. 代码与复现规范

### 8.1 每个实验的交付契约

每个已登记实验目录的共同最小资产为：

```text
README.md               # 目标、范围、资源、命令、预期输出
experiment-card.json    # 数据、环境、commit、资源、命令、指标和限制
src/                    # 本书自有实现或薄适配层；至少一个可测试模块
tests/                  # shape、schema、determinism、metric smoke tests
scripts/smoke.py        # S 档稳定入口；只输出结构化、确定性结果
```

小型参考结果统一放在仓库根目录 `results/chNN/`，由实验卡 `artifacts` 指向，避免实验目录和正文各维护一份数字。`config/`、`prepare`、`train`、独立 `evaluate/report`、checkpoint 和外部数据元数据只在实验确实需要时添加：训练实验必须把训练、评测和报告分开；纯解析/metadata fixture 可以让 `smoke`、`evaluate` 和 `report` 指向同一个确定性入口，不得为了目录整齐创建空配置或 no-op 脚本。

### 8.2 统一验收层级

实验卡状态与当前 Schema 一致：

1. `planned`：问题和路径已登记，但没有可发布结果；
2. `smoke`：S 档依赖、schema、算术/数据流、反例与结构化结果通过；不要求所有章节都训练模型；
3. `experimented`：适用的训练或目标方法运行完成，并用冻结协议评测；
4. `reviewed`：实验内容、代码、一致性和教学四审通过；
5. `reproducible`：锁定 commit、数据、环境和目标资源后完成冷启动复现。

`prepare/train/evaluate/stress/report` 是按实验适用性选择的执行阶段，不是实验卡状态。只要声称训练效果，`train` 与 `evaluate` 就必须分离；只要声称鲁棒或安全，必须增加相应 stress 与独立 gate，而不能因 S 档 smoke 通过就自动升级。

“成功安装”“能加载 checkpoint”“完成一次 rollout”“达到功能指标”必须分开报告。

### 8.3 第三方项目使用原则

- 优先薄适配，不复制大段第三方源码；
- 锁定 commit/tag、license、模型权重许可和数据许可；
- 区分官方实现、作者重实现和社区复现；
- 上游 README 的性能数字只能作为上游声明，除非达到 `R4`；
- 示例默认 Python + PyTorch；JAX 项目可通过容器或独立环境提供，不强行移植。

## 12. 出版与质量门禁

### 12.1 内容门禁

- 每章有明确问题、前置依赖、输出和下一章接口；
- 每个关键数字都有证据记录和核验日期；
- 每个公司能力声明都标注为来源方声明，除非有独立验证；
- 术语与第2章契约一致；
- 世界模型的生成质量与决策效用分别报告；
- 自动驾驶、机器人操作与人形案例不被混成同一证据域。

### 12.2 复现门禁

- 新环境按 README 可完成安装和 smoke；
- 所有参考结果记录代码 commit、数据版本、硬件、耗时和 seed；
- 训练型实验的训练、评测、报告命令分离；解析/metadata smoke 可复用同一确定性入口，但必须保留结构化结果和限制；
- 至少保留一个失败结果，避免只展示成功轨迹；
- 第三方项目升级必须先通过兼容矩阵，不直接更新到 main。

### 12.3 文档门禁

- 内部链接、引用键、图片来源、公式编号和术语自动检查；
- Markdown/Mermaid 严格构建；
- 代码片段来自可测试区域或明确标注为伪代码；
- 每次发布生成“资料截止日期、已验证实验、未验证声明、已知失效”的版本说明。

## 13. 已锁定的产品决策

以下决策自 v0.4 起作为实现约束（v0.6 更新了第3、4条）：

1. **3D 视觉零基础可读**：3D 视觉不是先修条件；第3章提供最小几何桥接，第12章从 RGB-D、点云和 BEV 开始。
2. **默认算力上限为 24GB 单卡**：所有必做训练遵守此上限；少数选做研究验证最多使用 2×80GB，并给出缩小版替代。每个实验还必须报告内存、磁盘、下载量、数据准备时间和总耗时；闭源 API 另报费用、延迟、限流和数据治理。
3. **仿真主线采用 MuJoCo/LIBERO**：基础控制使用 Gymnasium/DM Control，数据和策略接口
   使用 LeRobot；RoboCasa、Isaac Lab 为进阶扩展；MuJoCo MJX 作为 M/L1 档可选加速实现，切换前必须通过功能兼容与跨后端 rollout 对照。
4. **自动驾驶闭环 S/M 档默认改为 MetaDrive，CARLA 收窄为 L2 档感知/高保真选项**：MetaDrive 轻量、可 CPU 运行，承担默认闭环规划评测；CARLA（含录制数据）和公开驾驶视频数据集专门承担需要逼真多相机纹理的感知型练习，两者分工而非二选一。
5. **不要求购买实体硬件**：所有学习目标都必须能由离线数据或仿真完成；LeRobot 实体硬件仅为可选支线。
6. **仅做在线开源出版**：采用可执行仓库、版本化文档和活页案例卡，不为纸质篇幅牺牲证据、实验或更新机制。
7. **自动驾驶写入正文**：不只放在独立附录；按第4.1节贯穿定义、数据、世界模型、3D、仿真、评测、部署和综合项目。
8. **VLA 章节提供可选闭源提示基线**：版本锁定的商用 VLM API 可用于零样本/少样本对照，但不作为必做依赖，也不预设为性能下界；其本地显存与外部服务成本分别核算，动作必须经过独立安全层。
9. **当前开发阶段采用 CPU/Docker 优先**：当前设备没有可用 GPU，只执行文档构建、单元测试、CPU smoke、微型训练和小型 rollout。复杂依赖优先封装为锁定版本的 Docker/Compose 入口；完整数据集、大模型权重、GPU 训练和长时间实验延后执行，未经目标硬件实测的结果明确标为“待 GPU 验证”。

## 14. 全书成功标准

这份设计真正落地，不以“覆盖了多少模型”为标准，而以以下结果为标准：

- 读者能用一张闭环图解释全书；
- 任一新模型都能被放入四个判断轴，而不必新开一章；
- 两条贯穿实验线可以从冷环境运行；
- 没有 3D 视觉经验的读者能独立完成第12章的最小实验；
- 自动驾驶案例在正文形成从数据、建模到闭环评测的完整路径；
- 不购买实体硬件也能完成全部必做学习目标；
- 至少出现一次“预测更好但控制更差”的反例；
- 至少完成一次策略的统一协议比较和一次故障注入；
- 正文经典部分两年内无需重写，热点只更新案例卡；
- 任何“能力提升”都能追溯到数据、代码、评测和证据状态。
