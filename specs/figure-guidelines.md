# 图表规范

## 1. 图表类型

- 概念图：解释抽象关系，不声称对应具体代码；
- 架构图：对应论文架构或本书实现，必须注明来源；
- 时序图：描述真实接口、消息和时间关系；
- 实验图：由结构化结果自动生成；
- 对比表：确保任务、数据、硬件和指标可比较。

## 2. 必备元数据

每张图必须有稳定 ID、图注、alt text、源文件、生成命令、输入、导出文件和来源/许可。推荐目录：

```text
figures/ch06/FIG-06-01.mmd
figures/ch06/FIG-06-01.svg
figures/ch06/FIG-06-01.md
```

## 3. 绘制规则

- 架构图优先 Mermaid 或 SVG；
- 实验图只从 `results/` 中的 JSON/CSV 生成；
- 颜色不是唯一信息通道，同时使用线型、形状或标签；
- 每张图提供能够说明核心关系的 alt text，不能只写“示意图”；
- 坐标轴必须写名称、单位和统计方式；
- 截断坐标轴必须显式说明；
- 禁止手工平滑、移动或删除不利数据点；
- 原论文重绘、本书抽象和实际代码结构必须在图注中区分；
- 图中文字在常用移动端宽度下仍可读，Mermaid/SVG 不得裁剪节点或标签；
- 浅色、深色模式至少各检查一次，导出图避免依赖透明背景表达关键信息；
- AI 生成插图必须标注生成方式、人工修改和用途，不得作为实验或实物证据。

## 4. 审查问题

1. 图是否回答正文提出的问题？
2. 图中每个数字是否能追溯到实验 ID？
3. 图是否暗示了证据不支持的因果关系？
4. 不看颜色是否仍能理解？
5. 移动端和深色模式下是否可读？
6. alt text 是否传达了正文依赖的关系？
7. 图中文字、箭头和公式是否在导出后被裁剪？
