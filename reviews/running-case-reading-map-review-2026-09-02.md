# 全书贯穿案例、概念递进与阅读路径审查

> 日期：2026-09-02
> 范围：22章叙事接口、首页、导航与新增阅读地图
> 结论：以两个稳定任务补齐跨章连续性，不新增或合并实验结果

## 发现

22章篇幅约为1.0万到2.0万字符，每章已有契约、图表、练习、自检和下一章接口；问题不是内容不足，而是读者需要自行把相邻章节中的同名概念重新对齐。尤其是 `state`、`action`、`horizon`、`success` 和 `uncertainty` 会从教学抽象逐步升级为带frame、时间、分母和运行后果的工程合同。

自动驾驶已进入各章正文，但此前没有一条稳定场景从视频观测贯穿到route终测和MRM。对无3D经验读者，章节内虽有局部桥接，仍缺少“何时必须回看第3章、何时可以继续”的全书路线。

## 修订

新增 `docs/reading-map.md`，使用两个明确标为虚拟教学索引的任务：遮挡条件下移动杯子，以及施工改道中的切入车辆。页面完成三层连接：

1. 七个高频术语从早期直觉到后期合同的证据升级；
2. 22章逐章回答两个任务的新问题与新增最小证据；
3. 给出无3D经验读者和自动驾驶读者的可执行阅读顺序。

页面明确禁止把贯穿任务当共享数据集、把独立fixture拼成端到端运行，或由22个smoke推导机器人/车辆结果。MkDocs导航、首页入口和状态页同步更新。

`scripts/check_book.py` 新增阅读地图契约：每个manifest章节必须恰好链接一次，两个任务名称和七个核心术语必须保留，且必须同时声明“不是新增实验”和“独立smoke不是端到端证据”。对应接受/拒绝测试防止后续改目录或改叙事时静默破坏这条主线。

## 边界

本轮没有新增论文事实、CLAIM、FIG/TAB、实验卡、结果数字、代码fixture、外部数据、GPU、仿真或硬件运行。它提高的是概念连续性与检索效率；真实读者是否因此减少理解负担仍需后续人工测试。

## 验收

```text
make smoke-all
make docs-preview-check
make check
git diff --check
```

实际结果：22章共308个章节单元测试和22组固定smoke通过；结果JSON与登记artifact精确一致；严格规格检查覆盖4个schema、22章、22张实验卡、3张benchmark card和61项测试；站点检查覆盖29个HTML、22章、23张可访问Mermaid图、116个折叠式自检和1161个内部目标；`git diff --check` 返回0。
