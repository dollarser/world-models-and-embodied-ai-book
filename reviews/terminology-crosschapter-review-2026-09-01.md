# 全书术语与章节接口审查

> 日期：2026-09-01
>
> 范围：22 章正文、`specs/terminology.md`、`docs/glossary.md`、章节模板与本地质量门禁
>
> 结论：通过；没有改变实验结果、来源成熟度或 GPU/仿真状态

## 1. 发现的问题

1. 作者术语基线仍标为“草案”，与全书 `reviewed` 状态不一致；
2. RSSM、MPC、CEM、VLM、OOD、IDM、ESS、RLOO、RTC 以及 KL/NLL、MAE/RMSE、IoU、LPIPS/FVD 在正文中承担关键判断，但读者术语表没有统一入口；
3. 第1、5、7、8、18、22章把“小结与练习”或“接口与审查记录”合并为一个 H2，内容虽然存在，却削弱在线目录导航，也使模板完整性无法稳定自动检查；
4. 原有检查只验证标题层级，不验证教学区段和终章出口是否存在。

## 2. 本轮修改

- 将 `specs/terminology.md` 升级为已审查执行基线，并同步扩充读者术语表；
- 每个新增条目同时写明工作定义、容易混淆或“不能单独证明”的结论，以及首读章节；
- 在第7、9、15、18、21章补齐关键缩写首次出现时的全称；
- 拆分 6 章的“小结、练习、下一章/全书出口、验收与审查记录”，不改动原练习和审查结论；
- 新增章节区段与关键术语双侧覆盖检查：第1–21章必须有“下一章接口”，第22章必须有“全书出口”。

## 3. 准确性边界

- RSSM 是模型族，条目不把 DreamerV3 的 KL 路由或潜变量形式写成所有实现的定义；
- CEM 是近似优化器，不保证全局最优；MPC 的重规划不能消除模型错误；
- OOD 必须相对已声明的参考分布解释，分数不自动等于失败概率；
- ESS 必须声明 trajectory、transition、group 或 token 等计算单位；
- RLOO 在全同 reward 组中退化，重采样会改变任务分布；
- LPIPS/FVD、MAE/RMSE、IoU、KL/NLL 均只回答有限问题，不能替代动作语义、物理一致性、闭环效用或安全证据。

## 4. 验证与剩余限制

- 新增 4 个规格单元测试，覆盖编号式小结、终章出口、合并标题拒绝和作者/读者术语缺失的独立诊断；
- `make check` 通过：4 个 Schema、22 章、22 张实验卡、3 张 benchmark card 与 33 个规格测试均通过；
- `make docs-preview-check` 通过：27 个 HTML、22 个编译章节、23 张可访问 Mermaid 图和 1009 个内部目标均通过；
- `check_results.py` 确认 22 组 smoke 输出仍与登记结果 JSON 精确一致，`git diff --check` 通过；
- 自动检查只覆盖高频关键项是否存在，不判断所有段落的译名自然度、定义是否适合每类读者，也不替代人工内容审查；
- 本轮未运行 GPU、大数据、上游模型、仿真、机器人或车辆实验，所有既有资源与证据边界保持不变。
