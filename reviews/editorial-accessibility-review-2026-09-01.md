# 全书编辑结构与图表无障碍审查

> 审查日期：2026-09-01  
> 审查基线：`78b0e75` 之后的工作树  
> 范围：22 章长度与标题结构、跨章重复、23 张 Mermaid 图、1 张纯文本图、严格编译产物  
> 结论：关闭静态标题层级与 Mermaid 替代描述缺口；不把静态检查冒充完整视觉或屏幕阅读器验收

## 1. 编辑结构诊断

- 去除代码块后，各章正文约 6,031–12,705 字符；长章集中在快速演进的 VLA/WAM/系统内容，短章是导论与规划基础，没有仅凭长度机械扩写或裁剪；
- 22 章均以唯一 H1 开始，未出现 H2 直接跳 H4 等标题越级；
- 未发现长度至少 100 字符的整段跨章精确重复；共同边界如“smoke 不是性能复现”仍按各章对象具体化，而不是删除必要提醒；
- 章节长短和重复检测是定位工具，不是质量分数；概念闭合、前置知识与用途仍由人工审查判断。

## 2. 图表无障碍修复

全书 23 张 Mermaid 图此前有稳定 `FIG-*` 和视觉图注，但图本身没有 `accTitle/accDescr`。现在每张图都加入：

- 以登记 `FIG-NN-MM` 开头的短标题；
- 不依赖颜色、方向词或“示意图”空话的关系描述；
- 与 caption 不同的职责：`accDescr` 解释节点怎样连接，caption 继续记录来源、许可和证据边界。

第12章 `FIG-12-02` 是纯文本射线图，不经 Mermaid；其 `free/occupied/unknown` 字符含义由紧邻图注和正文逐项解释。表格继续依赖列标题、单元格和 `TAB-*` 图注表达结构。

## 3. 新增机器门禁

- `check_book.py` 拒绝缺失/过短的 Mermaid `accDescr`、没有登记 FIG ID 的 `accTitle`、跨章或重复 title；
- 标题检查拒绝多个 H1、首标题非 H1 和层级跳跃，并忽略代码块中的 `#` 示例；
- `check_site.py` 比对 Markdown 与严格构建 HTML 中的 `accTitle/accDescr` 数量，防止构建链静默丢失元数据；
- 新增 4 个正反向单元测试；规格合同测试由 25 增至 29。

## 4. 仍未完成的人工门禁

静态元数据存在不等于真实可访问。应用内浏览器自动控制接口本轮仍未暴露，因此没有伪造以下结论：深浅色对比度、320/768/1440 px 布局、200% 缩放、键盘焦点、Mermaid SVG 裁剪、VoiceOver/NVDA 朗读顺序。它们保持发布候选的人工待办，不影响当前证据范围受限的本地预览。
